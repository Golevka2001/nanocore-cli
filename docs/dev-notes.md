## 真机验证（USB-MIDI，macOS）

设备枚举为 `Nanocore` MIDI in/out 端口。预设索引 0 基（`select_preset(2)` 显示 `03`）。

| 命令               | 结果                                            |
| ------------------ | ----------------------------------------------- |
| `0x68` ping        | RX 9 B，seq 回显                                |
| `0x6D/0x02` 选预设 | RX `6d 00 00 02 00 00 09 <idx>`，设备切换       |
| `0x63` 快照        | RX 169 B，尾部含 chainOrder                     |
| `0x40` 预设列表    | RX 98 B，名字解码正确（`ClnArp`、`Ambient`、…） |

## 传输层要点

- 线上每帧带 SysEx 包装 `F0 7D 4E 43 ... F7`。`.mmon` 抓包里是裸帧（monitor 已剥包装）；发裸帧被静默忽略。`MidiTransport` 默认加包装。
- 设备每 ~250 ms 主动广播 `0x65`/`0x68` 帧，seq 用自己的计数器（`0x0Fxx`、`0x13xx`），与应答无关。
- 应答匹配 = 请求 seq 的精确回显；迟到的应答进 `pending` 缓冲，不丢弃。

## 帧格式

```text
7D 4E 43 | dir | flags | 02 | seq_lo | seq_hi | type | payload
```

- `dir`：`0x70` TX / `0x71` RX / `0x72` 主动事件
- `flags`：观察值 `0x00` 普通、`0x02` live、`0x22` preset-write、`0x40` RX
- byte 5 恒 `0x02`；`seq` LE u16，设备回显

## 元数据尾

app 在多数消息尾部附加设备生成的 compact state 块：

```text
DA 00 0E <u16 ids...> 5A "statusByte" 5E "clockTimestamp" ... 5D "From Nanocore"
```

字符串由设备固件产生（`libapp.so`/`liblivtra.so` 中不存在）。写入时是否必需未确认；`tail` 模块提供检测/剥离。

## `0x07` 参数写入

```text
00 07 00 [b3] 01 [b5] [b6] <float32 ×4, 7-bit-safe>
```

- `b6`：效果内参数序号
- `b5`：槽位（`0x00` fx1、`0x01` fx2，…，完整表见 `params_data`）
- `b3`：app 侧分片标记，按 8 步长循环 `0x00..0x38`，与寻址无关；真机验证单帧 `b3=0x00` 即生效

浮点编码：IEEE754 float32 LE，每字节最高位清零（`encode_param_value`）。强制——SysEx 传输中 `>= 0x80` 的字节即状态字节，整条消息被丢弃。4 字节 × 7 位 = 28 位有效；bit 23（指数 LSB）被清零，指数为奇数的值塌缩到更低偶指数（`0.3 → 0.1495`）。官方 app 相同：481 次旋钮扫描写入全部值字节 `< 0x80`。
