## CLI 编号约定

CLI 面向用户的编号一律 **1 起**（wire = N-1），与设备屏 / 官方 App 同号：

| CLI 输入/输出                                                                                                                          | wire              |
| -------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| 预设号 1–64（`preset set/list/show`、`debug probe`）；导入 `--slot` 1–40                                                               | 0–63（导入 0–39） |
| 型号 / 效果类型（`module <m> model`、`--type`、`show` 的 `type=`）                                                                     | 0 起              |
| 链位 / 模块编号 1–8（`chain set`、`debug enable`，顺序 = `CHAIN_ROLES`）                                                               | b5 = N-1          |
| 资产槽位：ir 1–30、amp 1–38（`asset`、`models`、`debug variant`）；`--amp-slot`/`--ir-slot` 1 起，**0 = unknown**（manifest 仍写 255） | 0 起              |
| `--ch` 1–16、`ports` / `--in-port` / `--out-port` 1 起                                                                                 | 0 起              |

**保持原始值**（裸线缆字节 / 量值，不做换算）：`module <m> param <b6>` 的数字键、
输出里的 `b5=` / `b6=`、`debug cc <cc> <value>`、`debug setparam b5 b6`、
`debug raw` / `replay`、音量/增益等 0–100 的值。本文其余部分描述协议，全部是
wire 值。

| 命令               | 结果                                            |
| ------------------ | ----------------------------------------------- |
| `0x68` ping        | RX 9 B，seq 回显                                |
| `0x6D/0x02` 选预设 | RX `6d 00 00 02 00 00 09 <idx>`，设备切换       |
| `0x63` 快照        | RX 169 B，尾部含 chainOrder                     |
| `0x40` 预设列表    | RX 98 B，名字解码正确（`ClnArp`、`Ambient`、…） |

## 传输层要点

- 线上每帧带 SysEx 包装 `F0 7D 4E 43 ... F7`。`.mmon` 抓包里是裸帧（monitor 已剥包装）；发裸帧被静默忽略。`MidiTransport` 默认加包装。
- 设备每 ~250 ms 主动广播 `0x65`/`0x68` 帧，seq 用自己的计数器（`0x0Fxx`、`0x13xx`），与应答无关。
- 应答匹配 = 请求 seq 的精确回显；迟到的应答进 `pending` 缓冲，不丢弃。

## 帧格式

```text
7D 4E 43 | dir | flags | 02 | seq_lo | seq_hi | type | payload
```

- `dir`：`0x70` TX / `0x71` RX / `0x72` 主动事件
- `flags`：观察值 `0x00` 普通、`0x02` live、`0x22` preset-write、`0x40` RX
- byte 5 恒 `0x02`；`seq` LE u16，设备回显

## 元数据尾

app 在多数消息尾部附加设备生成的 compact state 块：

```text
DA 00 0E <u16 ids...> 5A "statusByte" 5E "clockTimestamp" ... 5D "From Nanocore"
```

字符串由设备固件产生（`libapp.so`/`liblivtra.so` 中不存在）。写入时是否必需未确认；`tail` 模块提供检测/剥离。

## `0x07` 参数写入

```text
00 07 00 [MASK] 01 [b5] [b6] <float32 ×4, 各字节 & 0x7F>
```

- `b6`：效果内参数序号，同时也是快照记录里的数组下标（真机校准：二者逐位对应）
- `b5`：槽位（`0x00` fx1、`0x01` fx2，…，完整表见 `params_data`）
- `MASK`：**还原掩码**（不是寻址，也不是"分片标记"）。mask 第 _k_ 位 = 数据流第
  _k_ 字节的 bit7；数据流从 `01` 起算，所以 `bit0..2` ↔ `01/b5/b6`（恒 0），
  `bit(3+j)` ↔ 值字节 _j_。`protocol::param_write` 按值自动推导
  （`param_value_mask`），`debug setparam` 不再需要手写 `b3`。

把 mask 固定成 `0x00`（旧实现的 `DEFAULT_B3`）等于不声明任何被剥掉的 bit7，
设备会存成另一个数 —— 真机实测 `0.6→0.598`、`1.0→0.5`、`0.3→0.1495`、
`0.333→0.166`。带掩码写则 10/10 按 `round(v,3)` 精确入库。

浮点编码：IEEE754 float32 LE，每字节最高位清零后发出，被剥掉的位由 `MASK`
声明、接收方补回 —— **写入通路无损**。SysEx 中 `>= 0x80` 的字节即状态字节，
所以裸值必须 7-bit 安全（约 45.8% 的出厂参数值需要掩码）。唯一有损环节是
设备按 `round(v, 3)` 存储（千分之一网格；出厂 `.npreset` 里 1215/1215 个值
都在网格上）。

应答：

| 载荷             | 含义                                                  |
| ---------------- | ----------------------------------------------------- |
| 13 B             | 接受：`00 00 07 [MASK<<1] 00 01 b5 b6 v0 v1 v2 00 v3` |
| `00 01 00 00 00` | 拒绝：长度 / 字节非法                                 |
| `00 03 00 00 00` | 拒绝：`b6` 超出该模块的存储，**值保持不变**           |

`module <m> param` 检查 `00 03` 并报错（`protocol::PARAM_WRITE_REJECTED`），
而不是假装写入成功 —— `cab level`（b6=2，设备不存）就是被这条路径抓住的。
CLI 判定成败**只看 5 字节拒绝帧**，不解析 13 B 回显。
